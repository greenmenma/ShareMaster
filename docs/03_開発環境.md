# 03. 開発環境

コンテナは使用しません。DB は SQLite ファイル（`src/ShareMaster.Server/App_Data/sharemaster-dev.db`）です。

## 必要なもの

| ツール | バージョン | 備考 |
| --- | --- | --- |
| .NET SDK | 10.0 以上 | |
| Node.js | 22 以上 | npm 同梱 |
| IDE（任意） | VS Code（C# 拡張機能）/ Visual Studio 2026 / Rider | |

Windows・Mac のどちらでも同じ手順でデバッグできます。Docker は不要です。

## 起動

### Aspire（ダッシュボード付き）

```bash
dotnet run --project src/ShareMaster.AppHost
```

| リソース | 内容 |
| --- | --- |
| `server` | ASP.NET Core（起動時にマイグレーション適用・サンプルデータ投入） |
| `client` | Vite 開発サーバー（http://localhost:5173、`/api` を server にプロキシ） |

### Aspire を使わない場合

```bash
dotnet run --project src/ShareMaster.Server          # http://localhost:5148
npm --prefix src/ShareMaster.Client run dev          # http://localhost:5173
```

- API リファレンス（Scalar）：http://localhost:5148/scalar
- 開発 DB を初期化したい場合は Server を停止して `src/ShareMaster.Server/App_Data/` を削除してください（次回起動時に再作成）。

## VS Code でのデバッグ

必要な拡張機能：**C# 拡張機能（ms-dotnettools.csharp）**。C# Dev Kit は任意です。
「実行とデバッグ」ビューで構成を選んで F5 を押します。

| 構成 | 内容 |
| --- | --- |
| **全体: Server + Vite + Chrome** | 推奨。Server・Vite・Chrome を起動し、C# と React の両方にブレークポイントが効く |
| 全体: Server + Vite + Edge | 上記の Edge 版 |
| 全体: Aspire + Chrome | Aspire ダッシュボード付きで起動。Server のデバッグは「Server: プロセスにアタッチ」で `ShareMaster.Server` を選択 |
| Server | Server のみ（http://localhost:5148） |
| Aspire: AppHost | Aspire のみ（ダッシュボード：http://localhost:15140） |
| Server: プロセスにアタッチ | 実行中の Server（Aspire 起動時など）にアタッチ |
| Client: Vite 開発サーバー | Vite のみ（http://localhost:5173） |
| Client: Chrome / Edge でデバッグ | 起動済みの Vite にブラウザデバッガーを接続 |

- Vite のポートは Aspire 経由・単独起動とも **5173** に固定しています。
- 「全体」構成では Vite の起動を待たずにブラウザが開くことがあります。その場合は再読み込みしてください。
- テストのデバッグは C# Dev Kit の「テスト エクスプローラー」、Vitest 拡張機能から行えます。
- タスク（Ctrl/Cmd+Shift+B）：`build: solution`（既定）、`build: server`、`build: apphost`、`test: all`、`client: typecheck`

### その他の IDE

- **Visual Studio（Windows）**：`ShareMaster.slnx` を開き、`ShareMaster.AppHost`（または `ShareMaster.Server`）をスタートアップにして F5。
  React は `ShareMaster.Client`（.esproj）としてソリューションに含まれ、ソリューションのビルドで `npm install` / `npm run build` も実行されます。
- **Rider**：`ShareMaster.AppHost` または `ShareMaster.Server` の実行構成で Debug。

## 開発用ログイン

開発環境（`Auth:Mode=Development`）では Entra ID を使わず、ヘッダー右上のユーザーメニューからユーザーを切り替えられます。

| ユーザー | 役割（サンプルデータ） |
| --- | --- |
| 管理者 太郎（admin@dev.local） | システム管理者・本社の管理者 |
| 滋賀 花子（shiga@dev.local） | 滋賀・システムA の管理者 |
| 小牧 次郎（komaki@dev.local） | 小牧・システムB の管理者 |
| 一般 三郎（user@dev.local） | 閲覧のみ |

開発用ユーザーは `src/ShareMaster.Server/appsettings.Development.json` の `Auth:DevUsers` で変更できます。
本番環境（`ASPNETCORE_ENVIRONMENT=Production`）で `Development` モードを指定すると起動時にエラーになります。

## データベースとマイグレーション

DB 製品ごとに DbContext とマイグレーションを分けています（`Data/ProviderDbContexts.cs`）。

| Provider | DbContext | マイグレーション |
| --- | --- | --- |
| `Sqlite`（現在） | `SqliteShareMasterDbContext` | `Data/Migrations/Sqlite` |
| `SqlServer`（移行先） | `SqlServerShareMasterDbContext` | `Data/Migrations/SqlServer` |

**モデル（エンティティ）を変更したら、必ず両方にマイグレーションを追加してください。** 接続先は不要です。

```bash
dotnet tool restore
cd src/ShareMaster.Server
dotnet ef migrations add <名前> --context SqliteShareMasterDbContext    -o Data/Migrations/Sqlite
dotnet ef migrations add <名前> --context SqlServerShareMasterDbContext -o Data/Migrations/SqlServer
```

- 起動時（`Database:MigrateOnStartup=true`、既定）に自動適用されます。
- テストは SQLite のマイグレーションでスキーマを作成するため、マイグレーションの不備はテストで検出されます。
- SQL Server 固有の機能（ストアド等）は使わず、両方で動く範囲で実装してください。
