# 04. 本番環境構築

本番構成には Aspire を含めません。`ShareMaster.Server` を 1 つデプロイします（React は同梱）。
DB は **当面 SQLite** で運用し、将来 **SQL Server / Azure SQL Database** に移行できる構成です。

## 1. データベース

### 現在：SQLite

| 設定 | 値 |
| --- | --- |
| `Database__Provider` | `Sqlite`（既定） |
| `ConnectionStrings__ShareMasterDb` | `Data Source=<永続化されるパス>/sharemaster.db` |
| `Database__MigrateOnStartup` | `true`（既定。起動時にテーブル作成・更新） |

- 既定のパスは `App_Data/sharemaster.db`（アプリフォルダ配下）です。**デプロイで上書き・削除されない場所**を指定してください。
  - Azure App Service（Linux）：`Data Source=/home/data/sharemaster.db`
  - Azure App Service（Windows）：`Data Source=D:\home\data\sharemaster.db`
  - オンプレミス IIS 等：アプリフォルダ外のデータ用フォルダ
- フォルダが無い場合は起動時に作成します。
- バックアップは `.db` ファイル（および `-wal`／`-shm`）のコピーで行えます（停止中に取得するのが確実）。
- SQLite は同時書き込みに弱いため、**サーバーは 1 台（スケールアウトしない）**で運用してください。

### 移行：SQLite → SQL Server / Azure SQL Database

1. 空のデータベースを作成する（Azure SQL Database 等）
2. アプリを停止し、SQLite の `.db` ファイルを手元にコピーする
3. 移行先を設定してデータ移行コマンドを実行する（テーブル作成 → 全データを ID を保持したまま複写）

   ```bash
   # 発行済みフォルダで実行（PowerShell の場合は $env:変数名="値" で設定）
   export Database__Provider=SqlServer
   export ConnectionStrings__ShareMasterDb="Server=tcp:<server>.database.windows.net;Database=<db>;Authentication=Active Directory Default;Encrypt=True;"
   dotnet ShareMaster.Server.dll copy-data --from "Data Source=/path/to/sharemaster.db"
   ```

   - 移行先が空でない場合はエラーで中断します（二重移行の防止）。
   - 1 トランザクションで実行するため、途中で失敗した場合は何も登録されません。
4. 本番の設定を `Database__Provider=SqlServer` と SQL Server の接続文字列に変更して起動する

SQL Server 運用時の推奨：マネージド ID 認証。スキーマ変更を DBA が適用する場合は `Database__MigrateOnStartup=false` とし、
`dotnet ef migrations script --idempotent --context SqlServerShareMasterDbContext` で生成した SQL を適用してください。

## 2. Microsoft Entra ID アプリ登録

1 つのアプリ登録で SPA と API を兼ねる構成です。

1. Entra ID ＞ アプリの登録 ＞ 新規登録（シングルテナント）
2. **認証** ＞ プラットフォームの追加 ＞ **シングルページアプリケーション**
   - リダイレクト URI：`https://<本番ホスト名>/`
3. **API の公開**
   - アプリケーション ID URI：`api://<クライアントID>`
   - スコープの追加：`access_as_user`（管理者と利用者の同意）
4. （任意）エンタープライズアプリ ＞ プロパティで「割り当てが必要」を有効にし、利用者・グループを割り当て

## 3. アプリケーション設定（環境変数）

| キー | 値 |
| --- | --- |
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `Auth__Mode` | `EntraId` |
| `Auth__BootstrapAdmins__0` | 初期システム管理者の UPN（例：`taro@example.co.jp`） |
| `Auth__Spa__ClientId` | アプリ登録のクライアント ID |
| `Auth__Spa__Authority` | `https://login.microsoftonline.com/<テナントID>` |
| `Auth__Spa__Scopes__0` | `api://<クライアントID>/access_as_user` |
| `AzureAd__TenantId` | テナント ID |
| `AzureAd__ClientId` | クライアント ID |
| `AzureAd__Audience` | `api://<クライアントID>` |
| `Database__Provider` / `ConnectionStrings__ShareMasterDb` | 上記「1. データベース」参照 |
| `CanonicalUrl__RequireHttps` | `true`（既定。HTTP でのアクセスを HTTPS へリダイレクト） |
| `CanonicalUrl__HttpsPort` | リダイレクト先の HTTPS ポート（既定 443。443 以外のときのみ指定） |
| `CanonicalUrl__Domain` | ホスト名だけでアクセスされたときに付与するドメイン（例：`*.hoge.co.jp`。`hoge.co.jp` でも可） |

- `BootstrapAdmins` はシステム管理者が 0 人のときだけ登録されます。以降は画面から追加してください。
- 利用者は UPN（`preferred_username`）で識別します。
- 正規 URL へのリダイレクト（`CanonicalUrl`）：
  - 例：`http://server01/ShareMaster/` → `https://server01.hoge.co.jp/ShareMaster/`（HTTPS 化とドメイン付与を 1 回のリダイレクトで行う。パス・クエリは維持）
  - `localhost` と IP アドレスにはドメインを付与しません。
  - リダイレクトは 307（一時）です。設定を誤ってもブラウザにキャッシュされません。
  - 開発環境（`appsettings.Development.json`）では `RequireHttps` を `false` にしています。
  - IIS では HTTP（80）と HTTPS（443）の両方のバインドが必要です。証明書は FQDN（例：`*.hoge.co.jp` のワイルドカード証明書）のものを使います。

## 4. ビルド・デプロイ

```bash
dotnet publish src/ShareMaster.Server -c Release -o publish
```

- 発行時に `src/ShareMaster.Client` で `npm ci` → `npm run build` が実行され、`publish/wwwroot` に配置されます。
  - `npm ci` は `package-lock.json` が前回のインストールより新しい場合（依存パッケージが変わった場合）のみ実行され、それ以外は省略されます。強制的に入れ直したい場合は `src/ShareMaster.Client/node_modules` を削除してから発行してください。
- `publish` フォルダを Azure App Service（.NET 10）や IIS へデプロイします。
- GitHub Actions（`.github/workflows/ci.yml`）でビルド・テスト・発行物（アーティファクト）作成まで自動化しています。

### IIS の Default Web Site 配下のサブフォルダに配置する場合

例：`https://<ホスト>/ShareMaster/` で公開する場合。React はビルド時に配置先のパスを埋め込むため、`ClientBasePath` を指定して発行します。

```bash
dotnet publish src/ShareMaster.Server -c Release -o publish -p:ClientBasePath=/ShareMaster/
```

- 未指定の場合はサイトのルート（`/`）配置としてビルドされます。**配置先とビルド時の指定は必ず一致させてください**（不一致だと画面が真っ白・API が 404 になります）。
- サーバー側は ASP.NET Core Module が仮想パスを自動で扱うため、追加設定は不要です。

IIS の準備：

1. サーバーに **ASP.NET Core Hosting Bundle（.NET 10）** をインストールする
2. ShareMaster 用のアプリケーションプールを作成する（.NET CLR バージョン：**マネージドコードなし**）
3. `publish` の中身を配置したフォルダを、Default Web Site 配下に **アプリケーションとして追加**（エイリアス `ShareMaster`、上記プールを指定）
4. 環境変数（「3. アプリケーション設定」）は、発行物の `web.config` の `<aspNetCore>` 内に `<environmentVariables>` で設定するか、アプリケーションプール単位で設定する
5. SQLite の DB フォルダ（アプリフォルダ外）に、アプリケーションプール ID（`IIS AppPool\<プール名>`）の変更権限を付与する
6. Entra ID のアプリ登録（SPA）のリダイレクト URI に `https://<ホスト>/ShareMaster/` を登録する（大文字・小文字と末尾スラッシュまで一致させる）

注意：

- 親サイト（Default Web Site）の `web.config` の設定は子アプリにも継承されます。ハンドラー・モジュールの設定が競合する場合は親側で `<location inheritInChildApplications="false">` を使ってください。
- 動作確認の URL は `https://<ホスト>/ShareMaster/health` になります。

## 5. 動作確認

- `https://<ホスト>/health` が `Healthy` を返すこと
- ブラウザでアクセスし Entra ID のサインイン画面が表示されること
- 初期システム管理者でサインインし、メニューに「管理 ＞ システム管理者」が表示されること
